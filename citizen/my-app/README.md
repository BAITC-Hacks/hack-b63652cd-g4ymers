# E-AkimAI · Кабинет жителя

**Ваш район. Ваш голос. Укажите место на карте — сообщите, что нужно исправить.**

Кабинет жителя для HackAlem AI 2026. Обращения поступают в общий Spring Boot API и PostgreSQL, доступны акимату и учитываются в рейтинге района по обращениям. Оба кабинета используют логотип E-AkimAI, тёмную палитру и карту Астаны.

## Создать обращение — три шага

1. **Место на карте.** Откройте «Сообщить о проблеме», нажмите на нужную точку. Район определится автоматически. Введите адрес или ориентир и подтвердите: «Место на карте и адрес указаны верно».
2. **Что случилось.** Выберите направление, заполните заголовок, описание и срочность.
3. **Проверка.** Проверьте данные → «Отправить обращение». После ответа сервера появится номер заявки и ссылки на карточку и «Мои обращения».

**QR-код, камера и геолокация не нужны для этого пути.** Если на объекте есть QR-табличка, используйте дополнительный вход «Есть QR-код»: он подставляет зарегистрированное место. До нажатия кнопки отправки заявка не создаётся; при ошибке показывается сообщение.

## Карта и списки

- **Карта города:** локальная подробная подложка Астаны, пять районов задания — Есиль, Алматы, Сарыарка, Байконур и Нура — и девять ориентиров. Выбор района плавно приближает карту; точку можно уточнить кликом. За пределами пяти районов создать обращение через карту нельзя.
- **Управление:** перетаскивание левой кнопкой мыши или пальцем, масштаб колёсиком и кнопками «+»/«−», поворот зажатой правой кнопкой мыши. Кнопка `N` возвращает север наверх.
- **Отметки обращений:** собственные заявки и публичные решённые проблемы. Нажатие на отметку открывает краткую карточку со ссылкой на подробности.
- **Мои обращения:** личный список с фильтрами «Все», «Новые», «В работе», «Решённые» и кнопкой «Обновить список». Списки также обновляются после возврата в окно или вкладку и после отправки обращения.
- **Публичный журнал:** решённые обращения с поиском по названию, району или адресу и фильтрами направлений. Чужие активные заявки в него не попадают.
- **Карточка:** описание, адрес, статус, этапы обработки и переписка. В собственном активном обращении можно добавить комментарий.
- **Профиль:** показатели участия и баллы от сервера. Баллы жителя, рейтинг района по обращениям и Score сценария — разные показатели.

Активное обращение доступно автору и акимату. После решения карточка появляется в публичном журнале; личная переписка и идентификаторы автора в публичный ответ не входят. Содержимое описания решённой проблемы становится публичным.

## Два кабинета — общая работа

Житель отправляет обращение → аким находит его в «Обращениях» и меняет статус → житель видит обновление в личном списке.

В кабинете акима **рейтинг по обращениям** отражает активные проблемы и результаты обработки. **Score сценария** считает эффект выбранных инициатив по синтетическим показателям задания. Отправка или закрытие заявки не меняет сценарный Score; добавление инициативы не закрывает заявку автоматически. В AI-панели акима доступны рекомендации по темам и адресам обращений.

Для акима есть кнопка **«Как пользоваться»**: пять коротких разделов о сценарии, обращениях, рейтингах, AI и карте с переходами в соответствующие панели.

## Обучение и оформление

Гид жителя объясняет карту, выбор места, форму, статусы, публичный журнал и баллы. Его можно продолжить или запустить заново в «Помощи». Прогресс хранится отдельно для каждого аккаунта в этом браузере; обучение не создаёт заявок.

Оба кабинета используют палитру `#0D0F14`, `#2C303A`, `#5A82EC`, `#4F56B0`, `#78E2EA`, `#F4F5F1`, `#C8C9C7`. На телефоне карта и форма располагаются последовательно.

## Запуск

Нужны **Node.js 22.18+**, npm и работающий backend с PostgreSQL. Сначала выполните [инструкцию запуска API](../../backend/README.md) из корня репозитория.

Из корня репозитория:

```sh
cd citizen/my-app
npm ci
npm run dev -- --port 3001
```

Откройте [localhost:3001/citizen](http://localhost:3001/citizen) и зарегистрируйте жителя или войдите по ИИН и паролю. Проверки личности через eGov нет: это учётная запись приложения. Кабинет акима работает отдельно на порту 3000.

По умолчанию Next.js обращается к API на `http://127.0.0.1:8080`. Для другого адреса создайте `.env.local` в этой папке:

```dotenv
BACKEND_URL=http://127.0.0.1:8080
```

Перезапустите frontend после изменения адреса. Браузер обращается к `/api/backend/...`; Next.js передаёт запросы в Java API и хранит токен в отдельной HttpOnly-cookie жителя. Ошибки API не подменяются демонстрационными данными.

Production-запуск:

```sh
npm run build
npm start -- --port 3001
```

Production-cookie требует HTTPS. Для камеры и GPS на телефоне также нужен HTTPS; эти разрешения используются только в дополнительном QR-сценарии. Загрузка фотографий пока не реализована.

Синтетические жители и обращения создаются backend только при явном включении демонстрационного наполнения. Настройка описана в [документации backend](../../backend/README.md#синтетические-жители-и-безопасное-расширение-бд).

## Проверка

Команды из этой папки:

```sh
npm test
npm run lint
npm run build
```

HTTP-проверки создают жителей и обращения. Запускайте их **на отдельном тестовом backend и БД**. Оба frontend должны обращаться к этому одному API. Без переменных включения HTTP-тесты пропускаются.

Пример для PowerShell с тестовыми frontend на портах 3002 и 3003:

```powershell
$env:CITIZEN_API_TEST = '1'
$env:CITY_FLOW_TEST = '1'
$env:CITIZEN_FRONTEND_URL = 'http://127.0.0.1:3002'
$env:AKIM_FRONTEND_URL = 'http://127.0.0.1:3003'
$env:AKIM_TEST_EMAIL = 'email-отдельного-тестового-акима'
$env:AKIM_TEST_PASSWORD = 'пароль-отдельного-тестового-акима'
npm run test:integration
```

Тестовые frontend нужно запустить заранее; переменные `CITIZEN_FRONTEND_URL` и `AKIM_FRONTEND_URL` задают их фактические адреса. На Linux/macOS задайте те же переменные через `export`.

Команда запускает проверки последовательно: авторизация, cookie, приватность и баллы; затем обращение без QR → списки жителя и акима → изменение рейтинга → решение. Последовательность важна: обе проверки работают с районом Нура. Это инструкция запуска, а не утверждение о прохождении тестов в конкретном окружении.
