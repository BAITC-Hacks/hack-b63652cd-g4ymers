# Astana City API

Общий backend для кабинета жителя и симулятора акима: **Java 21+, Spring Boot 4.0.8, PostgreSQL 18, Flyway, Spring Security**.

Житель регистрирует проблему района. Аким рассматривает то же обращение, меняет статус и планирует городские меры в отдельном симуляторе. Все изменения обращений и сценарии сохраняются в PostgreSQL.

## Запуск на Windows

Из корня репозитория, PowerShell 7, установленный PostgreSQL 18 и Java 21+:

```powershell
.\backend\scripts\start-local-db.ps1
cd backend
.\mvnw.cmd package
cd ..
.\backend\scripts\start-api.ps1
```

API: `http://localhost:8080`. Проверка: `GET /api/health`.

Скрипт создаёт отдельный кластер `.local/postgres` на **127.0.0.1:55432**, базу `hackalem`, случайные пароли и локального акима. Учётные данные находятся в **`.local/dev-config.json`**, файл исключён из Git. Повторный запуск сохраняет данные и пароли. Остановка API — Ctrl+C; PostgreSQL:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' -D "$PWD\.local\postgres" -m fast stop
```

Для другого пути PostgreSQL: `start-local-db.ps1 -PostgresBin 'D:\PostgreSQL\18\bin'`.

## Запуск через Docker

Из корня: скопировать `.env.example` в `.env`, заменить оба пароля (пароль акима минимум 12 символов), затем:

```sh
docker compose up --build -d
```

API на `localhost:8080`, PostgreSQL на `localhost:5433`. Данные в Docker volume `city-db`. Локальный кластер Windows и Docker используют разные хранилища. Docker Compose подготовлен; проверка API выполнялась с локальным PostgreSQL.

## Датасет и расчёт

Flyway при первом запуске создаёт таблицы и загружает `V2__hackathon_dataset.sql`: **5 районов, 10 показателей с весами, 14 мер**. При следующих запусках Flyway не повторяет импорт.

Источник числовых значений: `Датасет районов.pdf` в корне репозитория. Это синтетические данные хакатона, не официальная статистика Астаны. Названия/описания мер адаптированы для интерфейса, числовая модель соответствует датасету.

| Район | Доля населения | Исходный районный Score |
|---|---:|---:|
| Есиль | 27% | 62.99 |
| Алматы | 24% | 57.06 |
| Сарыарка | 20% | 54.65 |
| Байконур | 13% | 56.63 |
| Нура | 16% | 49.18 |

Базовый городской Score **52.55768**. Пример из ТЗ: M7, M8, M10 в Нуре + M12 по городу + M5 в Сарыарке → бюджет **95**, Score **56.54307**, критических показателей **0** вместо 2.

Сервер проверяет: ровно 5 мер для завершения, стоимость ≤100, максимум 2 меры одного направления, уникальность мер, обязательный район локальной меры, отсутствие района у общегородской меры, все конфликты. Для черновиков допустимы 0–5 мер. Эффекты учитывают горизонт 8 кварталов, лаг и три синергии, значения ограничиваются 0–100, критический порог строго `<40`.

Исходные районы не меняются при симуляции. Результат сохраняется как снимок в сценарии; завершённый сценарий нельзя редактировать. Обращения сами по себе не меняют Score и не закрываются автоматически при выборе меры. `explanations` содержит объяснение формулы и синергий, сформированное кодом; LLM пока не подключена.

## Авторизация

`POST /api/auth/register` создаёт только `CITIZEN`. Поле `role` не принимается. Аким создаётся сервером через `AKIM_EMAIL` и `AKIM_PASSWORD`; существующему пользователю роль не повышается и пароль при перезапуске не сбрасывается.

```json
{"email":"resident@example.kz","password":"long-password-123","displayName":"Айдос","districtId":"nura"}
```

`POST /api/auth/login`: `{"email":"...","password":"..."}`. Оба метода возвращают `{token, expiresAt, user}`. Для защищённых запросов: `Authorization: Bearer <token>`. Токен действует 24 часа; в БД хранится только его SHA-256. Пароли — BCrypt. `GET /api/auth/me` возвращает пользователя, `POST /api/auth/logout` отзывает текущий токен.

CORS разрешает localhost/127.0.0.1 на портах 3000 и 3001; другие адреса задаются через `CORS_ORIGINS`. Cookie-аутентификация не используется.

## API

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `GET /api/health` | Все | Доступность API и БД |
| `GET /api/public/catalog` | Все | Районы, показатели, меры |
| `GET /api/public/baseline` | Все | Исходный расчёт |
| `GET /api/public/qr/{code}` | Все | Объект для обращения |
| `POST /api/akim/qr` | Аким | Зарегистрировать QR-объект |
| `POST /api/citizen/reports` | Авторизованный | Отправить обращение |
| `GET /api/citizen/problems` | Авторизованный | Лента обращений |
| `GET /api/citizen/my-reports` | Авторизованный | Только мои обращения |
| `GET /api/citizen/problems/{id}` | Авторизованный | Карточка обращения |
| `POST /api/citizen/problems/{id}/confirm` | Авторизованный | Подтвердить проблему, повтор не добавляет голос |
| `GET /api/citizen/problems/{id}/comments` | Авторизованный | Комментарии, по 50, `page=0` |
| `POST /api/citizen/problems/{id}/comments` | Авторизованный | Комментарий `{text}` |
| `GET /api/citizen/problems/{id}/history` | Авторизованный | История статусов |
| `GET /api/citizen/profile` | Авторизованный | Мои счётчики |
| `GET /api/akim/problems` | Аким | Общие обращения с фильтрами |
| `GET /api/akim/problems/{id}` | Аким | Карточка |
| `GET /api/akim/problems/{id}/history` | Аким | История |
| `PATCH /api/akim/problems/{id}/status` | Аким | Смена статуса |
| `POST /api/akim/simulation/preview` | Аким | Рассчитать план |
| `GET /api/akim/scenarios` | Аким | Собственные сценарии, по 20, `page=0` |
| `POST /api/akim/scenarios` | Аким | Создать черновик |
| `GET /api/akim/scenarios/{id}` | Аким-владелец | Получить сценарий |
| `PUT /api/akim/scenarios/{id}` | Аким-владелец | Обновить черновик |
| `POST /api/akim/scenarios/{id}/finalize` | Аким-владелец | Завершить сценарий |

Ленты возвращают массивы, совместимые по полям с `citizen/my-app/lib/citizen.ts`. Фильтры: `district=nura`, `status=NEW`, `category=SAFETY`, `page=0`, `size=20` (максимум 50). `district` в ответе — русское название, `districtId` — стабильный идентификатор. Карточка содержит первые 50 последних комментариев, остальные доступны отдельным запросом. `reportCount=1`: автоматическое объединение похожих обращений пока не реализовано.

Прямое обращение без QR:

```json
{
  "title":"Не горит фонарь",
  "description":"У перехода отсутствует освещение",
  "category":"SAFETY",
  "urgency":"IMPORTANT",
  "districtId":"nura",
  "locationLabel":"Адрес и ориентир",
  "latitude":51.1,
  "longitude":71.4
}
```

Для обращения по QR вместо района/адреса/координат передаётся `qrCode`. Сервер берёт местоположение из QR-объекта. Ответ: `{id, problemId}`. Один пользователь может подтвердить каждое открытое обращение один раз. Закрытые обращения не принимают новые подтверждения и комментарии.

QR-объект: `{code, districtId, objectName, objectType, latitude, longitude}`. QR-объекты не входят в исходный датасет и создаются отдельно, синтетические объекты автоматически не импортируются.

Статусы: `NEW → UNDER_REVIEW → PLANNED → IN_PROGRESS → RESOLVED`. Из `UNDER_REVIEW` разрешён переход сразу в `IN_PROGRESS`. Любое открытое обращение можно отклонить (`REJECTED`). Запрос: `{"status":"UNDER_REVIEW","version":0,"note":"Принято в работу"}`. Для `RESOLVED`/`REJECTED` пояснение обязательно. `version` берётся из текущей карточки; устаревшее значение даёт 409. История сохраняется в той же транзакции.

Предпросмотр: `{"selections":[{"id":"M7","district":"nura"},{"id":"M12"}],"complete":false}`. Создание черновика: `{"name":"Мой план","selections":[...]}`. При обновлении дополнительно передаётся `"version":0`. Завершение: `{"version":0}`. После обновления версия увеличивается.

Ошибки — `application/problem+json`, поле `detail`. Коды: 400 некорректный запрос, 401 нет токена/токен истёк, 403 нет роли, 404 нет объекта или доступа к сценарию, 409 конфликт версии/статуса/уникальности.

## Подключение интерфейсов

Backend реализован и проверяется через HTTP. Существующие фронтенды **пока продолжают использовать свои демонстрационные данные**. Для подключения нужно добавить вход и отправку Bearer-токена в клиенте citizen, затем заменить локальный расчёт/хранение сценариев akim на API. Одного `NEXT_PUBLIC_API_URL` недостаточно: текущий citizen-клиент не отправляет токен.

Фото-загрузка пока отсутствует. Поле `photoUrl` в запросе должно отсутствовать или быть `null`: текущее имя файла из формы не является загруженной фотографией и сервер его не сохраняет. Проверка географического попадания координат внутрь района также не реализована; валидируются район и диапазон координат.

## Проверки

```powershell
# В backend: тесты формулы, порогов, синергий и ограничений
.\mvnw.cmd test

# Из корня: HTTP-проверки с настоящим PostgreSQL в отдельной hackalem_test
.\backend\scripts\test-integration.ps1
```

Интеграционный тест проверяет миграции, вход, запрет повышения роли, разграничение доступа, обращения, мои обращения, повторные подтверждения, комментарии, конфликты версий, историю, QR, расчёт, финализацию и отзыв токена. Тестовые записи остаются только в `hackalem_test`; рабочая база `hackalem` не используется тестом.

Структура: `auth` — учётные записи и токены; `reports` — обращения и QR; `simulation` — каталог, формула и сценарии; `common` — JSON и ошибки. Доступ к PostgreSQL через параметризованные JDBC-запросы.
