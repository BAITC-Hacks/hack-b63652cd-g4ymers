# Astana City API

Общий backend для кабинета жителя и симулятора акима: **Java 21+, Spring Boot 4.0.8, PostgreSQL 18, Flyway, Spring Security**.

Житель регистрирует проблему района. Аким рассматривает то же обращение, меняет статус и планирует городские меры в отдельном симуляторе. Все изменения обращений и сценарии сохраняются в PostgreSQL.

## Запуск на Windows

Из корня репозитория, PowerShell 7, установленный PostgreSQL 18 и Java 21+:

```powershell
.\backend\scripts\start-local-db.ps1
cd backend
.\mvnw.cmd package
cd ..
.\backend\scripts\start-api.ps1
```

API: `http://localhost:8080`. Проверка: `GET /api/health`.

Скрипт создаёт отдельный кластер `.local/postgres` на **127.0.0.1:55432**, базу `hackalem`, случайные пароли и локального акима. Учётные данные находятся в **`.local/dev-config.json`**, файл исключён из Git. Повторный запуск сохраняет данные и пароли. Остановка API — Ctrl+C; PostgreSQL:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' -D "$PWD\.local\postgres" -m fast stop
```

Для другого пути PostgreSQL: `start-local-db.ps1 -PostgresBin 'D:\PostgreSQL\18\bin'`.

## Запуск через Docker

Из корня: скопировать `.env.example` в `.env`, заменить оба пароля (пароль акима минимум 12 символов), затем:

```sh
docker compose up --build -d
```

API на `localhost:8080`, PostgreSQL на `localhost:5433`. Данные в Docker volume `city-db`. Локальный кластер Windows и Docker используют разные хранилища. Docker Compose подготовлен; проверка API выполнялась с локальным PostgreSQL.

## Датасет и расчёт

Flyway при первом запуске создаёт таблицы и загружает `V2__hackathon_dataset.sql`: **5 районов, 10 показателей с весами, 14 мер**. При следующих запусках Flyway не повторяет импорт.

Источник числовых значений: `Датасет районов.pdf` в корне репозитория. Это синтетические данные хакатона, не официальная статистика Астаны. Названия/описания мер адаптированы для интерфейса, числовая модель соответствует датасету.

| Район | Доля населения | Исходный районный Score |
|---|---:|---:|
| Есиль | 27% | 62.99 |
| Алматы | 24% | 57.06 |
| Сарыарка | 20% | 54.65 |
| Байконур | 13% | 56.63 |
| Нура | 16% | 49.18 |

Базовый городской Score **52.55768**. Пример из ТЗ: M7, M8, M10 в Нуре + M12 по городу + M5 в Сарыарке → бюджет **95**, Score **56.54307**, критических показателей **0** вместо 2.

Сервер проверяет: ровно 5 мер для завершения, стоимость ≤100, максимум 2 меры одного направления, уникальность мер, обязательный район локальной меры, отсутствие района у общегородской меры, все конфликты. Для черновиков допустимы 0–5 мер. Эффекты учитывают горизонт 8 кварталов, лаг и три синергии, значения ограничиваются 0–100, критический порог строго `<40`.

Исходные районы не меняются при симуляции. Результат сохраняется как снимок в сценарии; завершённый сценарий нельзя редактировать. Обращения не изменяют **сценарный Score** и не закрываются автоматически при выборе меры. Отдельный **рейтинг по обращениям** учитывает актуальные записи PostgreSQL (описан ниже). `explanations` симулятора формируется кодом; внешняя LLM не требуется.

## Авторизация

`POST /api/auth/register` создаёт только `CITIZEN`. Поле `role` не принимается. Аким создаётся сервером через `AKIM_EMAIL` и `AKIM_PASSWORD`; существующему пользователю роль не повышается и пароль при перезапуске не сбрасывается.

```json
{"email":"resident@example.kz","password":"long-password-123","displayName":"Айдос","districtId":"nura"}
```

`POST /api/auth/login`: `{"email":"...","password":"..."}`. Оба метода возвращают `{token, expiresAt, user}`. Для защищённых запросов: `Authorization: Bearer <token>`. Токен действует 24 часа; в БД хранится только его SHA-256. Пароли — BCrypt. `GET /api/auth/me` возвращает пользователя, `POST /api/auth/logout` отзывает текущий токен.

CORS разрешает localhost/127.0.0.1 на портах 3000 и 3001; другие адреса задаются через `CORS_ORIGINS`. Java API использует Bearer; интерфейсы используют отдельные HttpOnly-cookie через Next.js-прокси.

Житель использует **ИИН + пароль**:

```text
POST /api/auth/citizen/register
{"iin":"990000000099","password":"your-long-password","displayName":"Тестовый житель","districtId":"nura"}

POST /api/auth/citizen/login
{"iin":"990000000099","password":"your-long-password"}
```

Проверяется формат 12 цифр и уникальность ИИН; пароль минимум 10 символов (не больше 72 байт UTF-8). ИИН не возвращается в DTO пользователя, публичных обращениях или рекомендациях. Это логин, **не проверка личности через eGov**; контрольная цифра намеренно не проверяется для синтетических аккаунтов. Перед публичным запуском нужны подтверждение личности, ограничение попыток входа, политика обработки ИИН и HTTPS. Старые email-аккаунты и вход акима сохранены.

Ленты возвращают массивы, совместимые по полям с `citizen/my-app/lib/citizen.ts`. Фильтры: `district=nura`, `status=NEW`, `category=SAFETY`, `page=0`, `size=20` (максимум 50). `district` в ответе — русское название, `districtId` — стабильный идентификатор. Карточка содержит первые 50 последних комментариев, остальные доступны отдельным запросом. `reportCount=1`: автоматическое объединение похожих обращений пока не реализовано.

Прямое обращение без QR:

```json
{
  "title":"Не горит фонарь",
  "description":"У перехода отсутствует освещение",
  "category":"SAFETY",
  "urgency":"IMPORTANT",
  "districtId":"nura",
  "locationLabel":"Адрес и ориентир",
  "latitude":51.1,
  "longitude":71.4
}
```

Для обращения по QR вместо района/адреса/координат передаётся `qrCode`. Сервер берёт местоположение из QR-объекта. Дополнительно принимается `location: {latitude, longitude, accuracy, capturedAt}`: возраст координат ≤5 минут, точность ≤150 м, расстояние до QR ≤250 м. Координаты браузера — вспомогательная проверка, не защита от подмены GPS. Если GPS недоступен, интерфейс позволяет явно подтвердить адрес вручную и не называет его проверенным. Ответ: `{id, problemId}`. Чужое активное обращение, переписка, история и действия над ним возвращают 404. У решённых общедоступна карточка, но переписка остаётся закрытой. Закрытые обращения не принимают новые подтверждения и комментарии.

QR-объект: `{code, districtId, objectName, objectType, latitude, longitude}`. Новое необязательное поле таблицы `street_name` задаёт адрес улицы; без него используется `object_name`. QR показывает последние решённые обращения этой точки и результат работы акима. Исторические сведения об улице не выдумываются: их пока нет в БД. Синтетические QR создаются только при явном включении демонстрационных данных.

Статусы: `NEW → UNDER_REVIEW → PLANNED → IN_PROGRESS → RESOLVED`. Из `UNDER_REVIEW` разрешён переход сразу в `IN_PROGRESS`. Любое открытое обращение можно отклонить (`REJECTED`). Запрос: `{"status":"UNDER_REVIEW","version":0,"note":"Принято в работу"}`. Для `RESOLVED`/`REJECTED` пояснение обязательно. `version` берётся из текущей карточки; устаревшее значение даёт 409. История сохраняется в той же транзакции.

Предпросмотр: `{"selections":[{"id":"M7","district":"nura"},{"id":"M12"}],"complete":false}`. Создание черновика: `{"name":"Мой план","selections":[...]}`. При обновлении дополнительно передаётся `"version":0`. Завершение: `{"version":0}`. После обновления версия увеличивается.

Ошибки — `application/problem+json`, поле `detail`. Коды: 400 некорректный запрос, 401 нет токена/токен истёк, 403 нет роли, 404 нет объекта или доступа к сценарию, 409 конфликт версии/статуса/уникальности.

## Подключение интерфейсов

Кабинет **akim подключён**: вход, каталог, исходный Score, серверный предпросмотр, сохранение/завершение сценариев, обращения и смена статусов. Next.js хранит токен в HttpOnly-cookie и передаёт Bearer-токен серверу Java через собственный `/api/backend/...`; адрес API задаётся серверной переменной `BACKEND_URL` (по умолчанию `http://127.0.0.1:8080`).

Кабинет **citizen подключён**: регистрация/вход по ИИН, QR, отправка обращений, свои заявки, публичный журнал решений, переписка и профиль с баллами из БД. `citizen_session` и `akim_session` независимы. Ошибка API показывается пользователю, а не заменяется демоданными. Next.js-прокси проверяет Origin для изменений, разрешённые пути и размер тела; токены не доступны JavaScript.

В `akim` и `citizen/my-app` установите `BACKEND_URL=http://127.0.0.1:8080` в `.env.local` (это серверный адрес, без `NEXT_PUBLIC_`). Затем в отдельных терминалах:

```sh
cd akim
npm ci
npm run dev -- --port 3000
```

```sh
cd citizen/my-app
npm ci
npm run dev -- --port 3001
```

Для камеры и геолокации на телефоне необходим HTTPS; простой LAN-адрес HTTP не является безопасным контекстом. Production-cookie также требуют HTTPS.

Фото-загрузка пока отсутствует. Поле `photoUrl` в запросе должно отсутствовать или быть `null`: текущее имя файла из формы не является загруженной фотографией и сервер его не сохраняет. Проверка географического попадания координат внутрь района также не реализована; валидируются район и диапазон координат.

## Живой рейтинг и рекомендации

Нажмите район на карте акима → «Рейтинг по обращениям». В «Предложениях ИИ» отображаются проблемные адреса, координаты, количество активных жалоб и разных жителей. Кнопка «Обновить» повторно читает БД. Изменения рейтинга не вмешиваются в планирование мер симулятора.

База — сумма десяти показателей района с весами PDF. Для каждой активной заявки нагрузка = вес направления / 0.20 × срочность (1 / 1.5 / 2). Все активные статусы учитываются независимо от возраста. Итог:

```text
штраф = 12 × ln(1 + нагрузка × 0.20 / доля_населения / 10)
бонус = 5 × (1 − exp(−решено_за_90_дней / 20))
рейтинг = clamp(база − штраф + бонус, 0, 100)
```

Новые активные проблемы снижают рейтинг до нижней границы 0; решение снимает нагрузку и добавляет ограниченный бонус. Отклонение снимает нагрузку, но не даёт бонуса. Коэффициенты 12/10/5/20 — прозрачная стартовая настройка, **не обученные параметры и не официальная оценка**. В PDF нет исторических меток качества районов для честного обучения регрессии. Рост обращений может отражать рост активности жителей, поэтому сравнение районов требует осторожности.

ML-часть — **multinomial Naive Bayes**, обучаемый на размеченной таблице `ml_training_samples`: сейчас 32 синтетических русскоязычных примера, 8 тем. Модель нормализует окончания слов, учитывает текст жалоб, при низкой уверенности воздерживается от конкретного совета. Активные жалобы группируются по теме, нормализованному адресу и сетке координат примерно 100 м; приоритет имеют группы с большим числом разных жителей. Советы основаны на шаблонах действий для найденной темы: нехватка баков → добавить ёмкость; переполнение/пропуски вывоза → проверить график и увеличить частоту. Решённые жалобы не создают активных рекомендаций.

Для улучшения добавляйте проверенные обезличенные примеры в `ml_training_samples(topic, body, source)` и оценивайте на отдельной отложенной выборке. Модель переобучается при запросе аналитики; файлы моделей и внешний AI API не нужны. Уверенность модели — не измеренная точность; качество на реальных обращениях пока не оценено. Автоматического расходования бюджета/закрытия заявок нет.

## Синтетические жители и безопасное расширение БД

Миграция `V3__citizen_identity_and_analytics.sql` добавляет ИИН, адрес QR, индекс аналитики и таблицу обучающих примеров. Старые пользователи, обращения, районы и сценарии сохраняются; перед применением миграций в рабочей БД сделайте резервную копию.

Демо-записи выключены по умолчанию. Для локальной демонстрации задайте backend-переменные (в Docker — корневой `.env`):

```dotenv
DEMO_RESIDENTS=true
DEMO_RESIDENT_PASSWORD=choose-your-own-demo-password
```

При запуске появятся **25 жителей**, по пять на район, **5 QR** и **75 обращений** (50 активных, 25 решённых). ИИН `990000000001`–`990000000025` содержат невозможный месяц `00` и не обозначают реальных людей. Пароль общий, берётся из вашей переменной; повторный запуск не меняет существующие пароли/статусы и не дублирует записи. Координаты и жалобы синтетические, не использовать для решений о реальном городе. QR: `DEMO-ESIL`, `DEMO-ALMATY`, `DEMO-SARYARKA`, `DEMO-BAIKONUR`, `ASTANA-NURA-LIGHT-001`. Например, откройте `/report/DEMO-ESIL` на citizen-сайте. После загрузки флаг можно выключить — данные сохранятся. В рабочем окружении не включать.

Поощрения хранятся через реальные обращения: 10 баллов за отправленное обращение, ещё 20 за решённое; значки за первое, пять и решённое обращение. Это демонстрационная схема без материальных выплат и пока без антиспам-модерации.

## Проверки

```powershell
# В backend: тесты формулы, порогов, синергий и ограничений
.\mvnw.cmd test

# Из корня: HTTP-проверки с настоящим PostgreSQL в отдельной hackalem_test
.\backend\scripts\test-integration.ps1
```

Интеграционный тест проверяет миграции, вход, запрет повышения роли, разграничение доступа, обращения, мои обращения, повторные подтверждения, комментарии, конфликты версий, историю, QR, расчёт, финализацию и отзыв токена. Тестовые записи остаются только в `hackalem_test`; рабочая база `hackalem` не используется тестом.

Тесты `AnalyticsTest` проверяют базы PDF, монотонность рейтинга, срочность, отклонения, классификатор на фразах вне обучающей выборки. HTTP-тесты также проверяют ИИН, приватность, геолокацию QR, журнал решений, изменение рейтинга и идемпотентность демоданных.

Frontend HTTP-тесты запускаются только с отдельным тестовым backend/БД; они создают записи:

```sh
# Из citizen/my-app, запущен citizen на 3001
CITIZEN_API_TEST=1 npm test
# Из akim, запущен akim на 3000
AKIM_API_TEST=1 AKIM_TEST_EMAIL=your-test-email AKIM_TEST_PASSWORD=your-test-password npm test
```

Структура: `auth` — учётные записи, демо и токены; `reports` — обращения и QR; `analytics` — рейтинг и ML-классификатор; `simulation` — каталог, формула и сценарии; `common` — JSON и ошибки. Доступ к PostgreSQL через параметризованные JDBC-запросы.
